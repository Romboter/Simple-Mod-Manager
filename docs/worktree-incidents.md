# Worktree & Sub-agent Incident Log

One-off failure modes hit while dispatching `isolation: "worktree"` sub-agents during the refactor batches. Kept for reference if the same symptoms recur — not everyday rules (those stay in `CLAUDE.md`'s Gotchas).

- **Stale-base-branch bug:** freshly-dispatched `isolation: "worktree"` sub-agents default their worktree's base branch to `origin/<default-branch>` (`fresh` policy) — a stale, pre-refactor commit that doesn't even have the `Views/MainWindow/` partial-file directory. Two agents hit this, didn't know how to recover, and silently ran their edits/git commands directly against the shared main worktree (`Simple-Mod-Manager-Refactor`) instead — this was only caught by noticing the main worktree's branch had unexpectedly changed. Fix: give the sub-agent the current branch tip commit hash and explicit permission to run `git reset --hard <hash>` **inside its own worktree only** as its first step, plus an explicit instruction to stop and report (never improvise by touching the shared worktree) if anything about its environment looks wrong. This fix worked cleanly for two subsequent retries. If a sub-agent's worktree ever needs re-verifying mid-batch, check `git worktree list` from the main worktree — a sub-agent's branch should advance past the stale base commit as it works.

- **Missing-worktree bug (distinct from the above):** occasionally an `isolation: "worktree"` dispatch never gets a worktree created for it at all — its `cwd` silently resolves to the shared main worktree instead. One agent this session caught it correctly (`git rev-parse --show-toplevel` pointed at `Simple-Mod-Manager-Refactor`, not a path under `.claude/worktrees/`) and stopped before writing anything. Its own `EnterWorktree` tool then refused to fix this ("cannot create a worktree from a subagent with a cwd override... spawn an Agent with `cwd` set to it instead") — a sub-agent can't self-heal this one. The only working fix is orchestrator-side: verify the shared worktree is still clean, abandon that agent instance, and dispatch a brand-new top-level `Agent` call with `isolation: "worktree"` for the same task. Tell every dispatched agent to check `git rev-parse --show-toplevel` resolves under `.claude/worktrees/` as part of its first-step environment check, not just the commit hash.

- **Sandbox-gate false alarm:** a sub-agent's own tool-permission prompt (e.g. for `git reset --hard`) can come back denied/garbled with something like "the user pushed back with 'what is this for?'" — that is the sub-agent's sandbox gate, not an actual message from the orchestrating session. If a dispatched agent reports this, just resume it (`SendMessage`) confirming it should proceed as originally instructed.
